# Solutions for D18-T001

Open this only after attempting the exercises in the topic note.

## Exercise 1

Split into `InvoiceReader`, `InvoiceWriter`, and `PaymentCoordinator`; keep DTOs as transport types without behavior. Inject `PaymentPort` into the coordinator so checkout does not construct Stripe directly.

## Exercise 2

`new StripeClient()` (or equivalent) inside `InvoiceService` breaks DIP—the service depends on a concrete detail. Inject `PaymentPort` in the constructor and bind `StripeAdapter` only in the composition root.

## Exercise 3

Interfaces on stable DTOs add noise and force empty adapter methods; interfaces on IO ports (`PaymentPort`, `NotificationPort`) add testability. Apply ISP: split fat ports, do not wrap every data class.
