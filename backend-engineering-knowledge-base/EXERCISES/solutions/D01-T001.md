## Exercise 1

```python
def parse_limit(raw: str, default: int = 20, upper: int = 100) -> int:
    if raw is None or raw.strip() == "":
        return default
    value = int(raw, 10)  # ValueError on malformed text
    if not 1 <= value <= upper:
        raise ValueError(f"limit must be between 1 and {upper}")
    return value


def parse_user_id(raw, bit_width: int = 32) -> int:
    if isinstance(raw, bool) or not isinstance(raw, (int, str)):
        raise ValueError("user id must be an integer or a base-10 string")
    value = int(raw, 10) if isinstance(raw, str) else raw
    if isinstance(raw, str) and raw.strip() != str(value):
        raise ValueError("user id must be a canonical base-10 integer")
    if value < 1 or value > (1 << bit_width) - 1:
        raise ValueError("user id out of range")
    return value
```

Acceptance notes: `int("010")` is 10, and `str(10) != "010"`, so the canonical check rejects padded ids if you require that. Boolean `True` is rejected because `bool` is checked before `int`. This solution was not executed as a separate test file. The sibling example `d01_t001_types.py` was executed.

## Exercise 2

The charge display is a binary floating-point artifact. `0.10` is not exact in IEEE 754. Three additions accumulate the error. Migrate the column to `bigint` cents or `numeric(12, 2)`. Do the percentage in integer arithmetic. Regression amounts: `0.10` and `19.99`. Rounding rule to publish: half away from zero on the minor unit, applied once at the end, not on each intermediate float.
