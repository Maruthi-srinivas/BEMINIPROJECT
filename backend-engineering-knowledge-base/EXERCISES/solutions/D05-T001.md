# Solutions for D05-T001

Open this only after attempting the exercises in the topic note.

## Exercise 1

For **Client-server architecture**, a solid answer names concrete components (clients, load balancers, handlers, data stores) and trust boundaries. Implementation exercises should include a diagram or module list checked by a peer. Acceptance: another engineer can deploy or test from your write-up without guessing hidden steps.

## Exercise 2

Debugging should start from a single failing request id or trace, then compare dependency metrics (database, cache, provider) against application logs. State the hypothesized root cause, the minimal reproduction, and the mitigation (rollback, flag, or config). Acceptance: you distinguish client, server, and dependency faults with evidence.

## Exercise 3

Trade-off answers compare at least two options with benefits, costs, and when each wins. Tie the decision to SLIs, team size, and compliance needs. Acceptance: you mention failure modes and how you would validate the choice in staging before production.

Narrative for this topic:

- Exercise 1 focus: Sketch a deployment diagram for a mobile app, CDN, API gateway, three microservices, and two databases. Label trust boundaries.
- Exercise 2 focus: A team puts business SQL in the mobile app. List three risks and where that logic should live instead.
- Exercise 3 focus: Compare thick client versus thin client for an inventory app: offline needs, consistency, and release cadence.
