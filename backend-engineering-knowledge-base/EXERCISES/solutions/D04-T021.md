# Solutions — D04-T021

## Exercise 1

A CDN caches content at edges close to users and terminates TLS there. It reduces origin load and RTT for cacheable bytes. The origin still owns uncacheable and personalized responses. Cache keys must include every input that changes the body. A purge has to be explicit because TTL is the other way an object leaves.

The failure enters when a step is skipped or repeated without an invariant: caching a response that varies by cookie under a key that ignores the cookie.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose CDN and edge networking when the bytes are public and larger than the header overhead.

Avoid it when the response is unique per user or must be consistent immediately after a write.

A good answer names the metric that would change your mind: edge hit ratio and origin request rate after a purge.
