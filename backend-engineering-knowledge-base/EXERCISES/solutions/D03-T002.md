# Solutions for D03-T002

## Exercise 1

Run the section F example; while parent sleeps, `ps -o pid,stat,cmd -p <child_pid>` shows `Z`. After `waitpid`, child vanishes. Not executed in CI.

## Exercise 2

Causes: (1) cgroup CPU quota throttling—check `cpu.stat` `nr_throttled`; (2) too many runnable threads vs cores—`loadavg`, `mpstat`; (3) lock contention making threads runnable but spinning—profile `futex`. CPU low because threads wait on run queue or I/O, not computing.

## Exercise 3

Prefork: many processes, high memory, strong isolation, slow fork on spike. Threaded/async single process: one accept loop with epoll, few threads—low idle RAM, shared state risk. For 10k idle connections prefer event-driven single process (epoll/kqueue) over 10k prefork processes.
