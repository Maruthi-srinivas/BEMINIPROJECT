# Solutions for D05-T006

Open this only after attempting the exercises in the topic note.

## Exercise 1

For **Configuration and environment variables**, a solid answer names concrete components (clients, load balancers, handlers, data stores) and trust boundaries. Implementation exercises should include a diagram or module list checked by a peer. Acceptance: another engineer can deploy or test from your write-up without guessing hidden steps.

## Exercise 2

Debugging should start from a single failing request id or trace, then compare dependency metrics (database, cache, provider) against application logs. State the hypothesized root cause, the minimal reproduction, and the mitigation (rollback, flag, or config). Acceptance: you distinguish client, server, and dependency faults with evidence.

## Exercise 3

Trade-off answers compare at least two options with benefits, costs, and when each wins. Tie the decision to SLIs, team size, and compliance needs. Acceptance: you mention failure modes and how you would validate the choice in staging before production.

Narrative for this topic:

- Exercise 1 focus: List config that belongs in env versus config file versus feature flag service.
- Exercise 2 focus: A staging pod reads production DATABASE_URL. Write the deploy checklist that prevents this.
- Exercise 3 focus: Implement validation that fails startup when PORT is not an integer.
