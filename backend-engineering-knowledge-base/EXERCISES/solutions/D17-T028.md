# Solutions — D17-T028

## Exercise 1

A distributed cache spreads keys across nodes so memory and throughput exceed one machine. Clients hash a key to a node. Consistent hashing or numbered slots reduce movement when a node is added. Replication covers a node failure and can serve stale reads. The hard problems are hot keys, thundering herds, and invalidation when the database changes. The cache is not the system of record.

The failure enters when a step is skipped or repeated without an invariant: a hot key on one node, or a cold start that melts the database.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Distributed cache when a read working set is hot and larger than one cache node, and the database remains authoritative.

Avoid it when you store the only copy of a payment in the cache.

A good answer names the metric that would change your mind: hit ratio, per-node CPU, and database QPS during a cache failure.
