## Exercise 1

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class LineItem:
    sku: str
    qty: int


def freeze_items(raw: list[tuple[str, int]]) -> tuple[LineItem, ...]:
    return tuple(LineItem(sku=s, qty=q) for s, q in raw)


def assert_no_alias(a: list, b: list) -> None:
    if a is b:
        raise ValueError("lists must not be the same object")
```

After `freeze_items`, changing `raw.append(...)` does not alter the tuple. Mutating a `LineItem` field raises `FrozenInstanceError`. This solution is unexecuted as a separate test file.

## Exercise 2

The service is a singleton but `currentUser` is request-specific mutable state written on every HTTP call. Concurrent requests overwrite each other’s user, producing cross-account leakage. Fix: store the user on a request-scoped object (`RequestContext`, MDC, or `@RequestScope` bean) or pass `UserSnapshot` as an immutable argument through the call stack. After authentication, build a frozen user record and never mutate it for the remainder of the request.

## Exercise 3

Immutable event records allocate a new object per publish but eliminate races and partial reads on a shared map. A reused mutable map is faster only if a single thread clears and repopulates it before handoff, and no async consumer retains a reference to the old contents. Prefer immutable records (or serialized bytes) on the bus so subscribers log consistent payloads. If allocation dominates, batch events or use binary schemas, not a shared mutable map visible to multiple threads.
