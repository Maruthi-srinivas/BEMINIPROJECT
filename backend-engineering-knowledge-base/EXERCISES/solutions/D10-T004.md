# Solutions — D10-T004

## Exercise 1

A wide-column store groups rows by a partition key and stores many columns or cells inside that partition, often sorted by a clustering key. Cassandra and Bigtable are the reference designs. Reads are fast when they hit one partition. A query that scans every partition is a distributed full scan. The data model is the query model.

The failure enters when a step is skipped or repeated without an invariant: a hot partition or a query that fans out because the WHERE clause is not the partition key.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Wide-column databases when the access path is a known key and a range inside one partition.

Avoid it when you need ad hoc queries across many partitions.

A good answer names the metric that would change your mind: partition size, p99 of the primary query, and fan-out count.
