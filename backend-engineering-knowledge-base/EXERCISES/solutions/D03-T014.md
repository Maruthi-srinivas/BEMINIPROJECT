# Solutions — D03-T014

## Exercise 1

Virtual memory gives each process its own address space. The CPU translates virtual pages to physical frames through page tables. The process cannot name another process's memory except through an explicit shared mapping. Overcommit and swap let the OS promise more virtual memory than RAM, and then the promise fails under pressure.

The failure enters when a step is skipped or repeated without an invariant: the OOM killer, or latency spikes when anonymous memory is swapped out.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

Watch major page faults, swap in/out, and RSS versus the cgroup limit. A test that only checks a 200 status does not lock the invariant.

Choose Memory management and virtual memory when you are explaining a crash, a leak, or a container limit.
