# Solutions for D06-T003

## Exercise 1

`GET/HEAD` list/detail; `POST /widgets` create; `PUT /widgets/{id}` replace; `PATCH` selective fields; `DELETE` remove. Pause: `POST /widgets/{id}/pauses` with idempotency key or `PUT` status to `paused` idempotently.

## Exercise 2

Store `(tenant, idempotency_key) -> {status_code, headers, body_hash, response}` with TTL 24h; reject same key with different body hash using `409`; return cached response on replay; unique DB constraint on payment idempotency key.

## Exercise 3

Signup: `POST` with server-generated id reduces enumeration and simplifies email uniqueness; offer optional client UUID only if mobile offline create needs `PUT` idempotency. Document retry policy accordingly.
