# Solutions — D20-T023

## Exercise 1

Fault injection and chaos testing deliberately break a dependency, a host, or a network path to see whether the system degrades as designed. Start with a hypothesis and a blast radius. Abort the experiment if the user impact exceeds the budget. The result is a fixed gap or a confirmed fallback, not a green dashboard. Production experiments need an owner.

The failure enters when a step is skipped or repeated without an invariant: an experiment with no abort condition that becomes the outage, or a test that only kills a process in a way production will not.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Fault injection and chaos testing when you claim a fallback or a timeout and have never seen the fault.

Avoid it when you inject faults with no hypothesis and no stop button.
