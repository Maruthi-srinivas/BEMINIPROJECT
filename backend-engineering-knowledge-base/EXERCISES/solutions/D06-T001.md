# Solutions for D06-T001

Open this only after attempting the exercises.

## Exercise 1

Typical gaps: in-memory sessions (statelessness), missing `Cache-Control` on catalog (cacheability), verb-style URLs like `/createUser` (uniform interface). Symptom for sessions: logout on rolling deploy. Mitigation: JWT or `sessions/{id}` resource, plus cache headers on read models. Document which Richardson level you target.

## Exercise 2

If sessions live in Tomcat memory on one pod, deploy kills them. Diagram: client cookie → load balancer → pod RAM map. Replacement: signed access token in `Authorization` validated every request, optional refresh token rotation, or server-side session row keyed by `session_id` the client stores. Propagate `request_id` for support without pod names.

## Exercise 3

Refunds: `POST /orders/{order_id}/refunds` with `Idempotency-Key` (see `D06-T011`). Subscriptions: `POST /customers/{id}/subscriptions` and `PATCH` for plan changes. Keep `POST /execute` only behind an internal gateway for batch jobs where no public client exists; external surface stays resource-oriented for observability and cache policy.
