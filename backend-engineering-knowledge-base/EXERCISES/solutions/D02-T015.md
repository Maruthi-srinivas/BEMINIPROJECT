## Exercise 1

```python
from typing import Callable, List, TypeVar

T = TypeVar("T")


def merge_sort_stable(arr: List[T], key: Callable[[T], object]) -> List[T]:
    if len(arr) <= 1:
        return arr[:]
    mid = len(arr) // 2
    left = merge_sort_stable(arr[:mid], key)
    right = merge_sort_stable(arr[mid:], key)
    out: List[T] = []
    i = j = 0
    while i < len(left) and j < len(right):
        if key(left[i]) <= key(right[j]):
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    out.extend(left[i:])
    out.extend(right[j:])
    return out


def lower_bound(sorted_arr: List[int], target: int) -> int:
    lo, hi = 0, len(sorted_arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if sorted_arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

Acceptance notes: stability comes from taking from the left when keys tie. `lower_bound` returns `len(arr)` if all elements are smaller than target. This solution was not executed as a separate test file.

## Exercise 2

The bug is treating a rotated sorted array as globally sorted, so the monotonic predicate for binary search is false. Fix: run O(n) rotation-index detection then binary search on one segment, or one modified binary search that compares against `nums[0]` to decide which half is sorted—still O(log n) time, O(1) space. Sorting first costs O(n log n) but simplifies code for batch queries.

## Exercise 3

Page 1 offset: O(k) with index on `(created_at DESC, id DESC)` if the engine can read the first k rows. Page 10,000 with `OFFSET 100000 LIMIT k`: O(offset + k) row visits, often unacceptable. Keyset: `WHERE (created_at, id) < (?, ?) ORDER BY created_at DESC, id DESC LIMIT k` is O(k) per page with the same composite index. Publish the cursor tuple in the API response.
