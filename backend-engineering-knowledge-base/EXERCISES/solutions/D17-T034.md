# Solutions — D17-T034

## Exercise 1

An audit log service records who did what to which object, and when, in a form that is append-only for investigators. It is not the debug log. Entries are written in the same transaction as the change when the answer must not diverge, or via an outbox. Queries are by actor, object, and time. Retention is a legal requirement. The log itself needs access control.

The failure enters when a step is skipped or repeated without an invariant: an audit row written only after a later request succeeds, so a crash leaves a change with no record, or an audit API that leaks other tenants.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

The assertion should fail when an audit row written only after a later request succeeds, so a crash leaves a change with no record, or an audit API that leaks other tenants.

Watch gaps between commits and audit rows, and unauthorized audit reads. A test that only checks a 200 status does not lock the invariant.
