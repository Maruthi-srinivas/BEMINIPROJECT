# D31-T003 interview items

Domain: Backend Frameworks — Choose One Deeply
Topic: Spring Security
Difficulty mix: beginner, intermediate, advanced, scenario, follow-up
Interview type: fundamentals, debugging, trade-off
Full reasoned answers are in the topic note, section K.

## Questions

1. Beginner. What problem does Spring Security solve in a backend system?
2. Beginner. What are the main components involved in Spring Security?
3. Beginner. How does Spring Security show up at an API boundary?
4. Beginner. What is a common misconception about Spring Security?
5. Beginner. Which metric would you watch first after enabling Spring Security?
6. Intermediate. Walk through the request path for Spring Security under normal load.
7. Intermediate. How would you test Spring Security before a production rollout?
8. Intermediate. What consistency or durability guarantees matter for Spring Security?
9. Intermediate. How does Spring Security interact with retries and timeouts?
10. Intermediate. Where would you place authorization checks relative to Spring Security?
11. Advanced. What failure modes are unique to Spring Security at scale?
12. Advanced. How would you design Spring Security for multi-region or multi-tenant isolation?
13. Advanced. Compare two implementation options for Spring Security and pick one with reasons.
14. Advanced. How do you prevent Spring Security from becoming a single point of failure?
15. Advanced. What load or chaos tests would you run for Spring Security?
16. Scenario. Latency spikes right after a deploy touching Spring Security. What do you check first?
17. Scenario. One tenant reports errors while others are healthy. How does Spring Security factor in?
18. Scenario. Costs doubled after enabling Spring Security. How do you investigate?
19. Scenario. A dependency used by Spring Security is slow but not down. What mitigations apply?
20. Scenario. An audit asks for evidence that Spring Security is enforced. What artifacts do you provide?
21. Follow-up. How does Spring Security relate to observability and SLOs?
22. Follow-up. Which earlier database or networking topics does Spring Security assume?
23. Follow-up. What would you study next after mastering Spring Security?
