# Solutions — D13-T020

## Exercise 1

A concurrency limit caps how many operations of one kind may run at once. A bulkhead isolates that cap so a failure in one dependency cannot consume every thread. Separate pools for separate dependencies stop a slow payments call from occupying the threads the health check needs. The limit should match the dependency, not the size of the machine.

The failure enters when a step is skipped or repeated without an invariant: one slow dependency occupying the only thread pool so the process cannot serve even cached reads.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

The assertion should fail when one slow dependency occupying the only thread pool so the process cannot serve even cached reads.

Watch pool saturation per dependency, and success of an isolated health check during that saturation. A test that only checks a 200 status does not lock the invariant.
