# Solutions for D28-T001

Open this only after attempting the exercises in the topic note.

## Exercise 1

Make `TenantContext` a required constructor argument on repositories (`OrderRepository(ctx)`). Expose only methods like `get_order(order_id)` that internally bind `tenant_id` in SQL. Tests: (1) happy path returns order for tenant A, (2) tenant B cannot read tenant A order by id, (3) repository construction without context fails or uses a null-object that raises `TenantRequiredError` on any call.

## Exercise 2

Root cause: cache key was `order:{id}` without tenant; two tenants reused the same external id or internal id collision after migration. Fixes: change key to `t:{tenant_id}:order:{id}`, bump cache version on deploy, flush affected namespace, add integration test that two tenants with same business key do not share cache entries.

## Exercise 3

SMB on shared-table with strict ORM scopes and RLS optional; enterprise on database-per-tenant or schema-per-tenant with dedicated pool and SLA. Routing: token claim `tier` selects datasource; control plane stores DSN per enterprise tenant. Document migration path for an SMB that upgrades to enterprise.
