# Solutions — D17-T024

## Exercise 1

A distributed task queue accepts a unit of work, stores it durably, and hands it to one of many workers. The API is enqueue and status. At-least-once delivery means workers must be idempotent. A visibility timeout hides a task while a worker runs it and returns it if the worker dies. The queue depth and the age of the oldest task are the capacity signals. A single consumer process is not this design.

The failure enters when a step is skipped or repeated without an invariant: two workers running the same task because the lease expired, or a poison task blocking one partition.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 2

The assertion should fail when two workers running the same task because the lease expired, or a poison task blocking one partition.

Watch oldest task age, lease expirations, and duplicate execution count. A test that only checks a 200 status does not lock the invariant.

## Exercise 3

Choose Distributed task queue when work must survive the API process and run on a pool of workers.

Avoid it when the work is a request-scoped function that can finish before the HTTP response.

A good answer names the metric that would change your mind: oldest task age, lease expirations, and duplicate execution count.
