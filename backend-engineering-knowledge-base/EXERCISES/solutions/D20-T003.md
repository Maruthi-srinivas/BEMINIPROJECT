# Solutions — D20-T003

## Exercise 1

A component test checks one service or module through its external interface while replacing the systems it depends on with fakes you control. It sits between a unit test and a full end-to-end test. The fake must implement the contract you actually rely on. If the fake is kinder than production, the test is fiction.

The failure enters when a step is skipped or repeated without an invariant: a fake that never times out or returns an error, so production failures are untested.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 2

The assertion should fail when a fake that never times out or returns an error, so production failures are untested.

Watch bugs found only in staging that the component tests could have injected. A test that only checks a 200 status does not lock the invariant.

Choose Component testing when you want the service's behavior without the real neighbors.
