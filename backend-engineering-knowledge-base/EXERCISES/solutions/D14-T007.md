# Solutions — D14-T007

## Exercise 1

A partition key hashes to a partition. All records with the same key share that partition's order. Different keys do not. A null key spreads records and loses per-entity order. A hot key pins a partition. The key should be the entity whose order you care about, and it should have enough cardinality.

The failure enters when a step is skipped or repeated without an invariant: a hot key that makes one partition lag while others are idle, or a missing key that reorders a user's events.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 2

The assertion should fail when a hot key that makes one partition lag while others are idle, or a missing key that reorders a user's events.

Watch bytes and lag per partition, and the hottest key's share. A test that only checks a 200 status does not lock the invariant.
