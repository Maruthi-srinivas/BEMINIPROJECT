# D14-T001 interview items

Domain: Messaging and Event-Driven Architecture
Topic: Message queues vs event streams
Difficulty mix: beginner, intermediate, advanced, scenario, follow-up
Interview type: fundamentals, trade-off, debugging
Full reasoned answers are in the topic note, section K.

## Questions

1. Beginner. What is the main purpose of a message queue?
2. Beginner. What is an event stream in messaging terms?
3. Beginner. How do competing consumers differ from multiple consumer groups on a stream?
4. Beginner. What does message acknowledgment mean for a queue?
5. Beginner. Why would you choose asynchronous messaging instead of synchronous HTTP?
6. Intermediate. When is a queue a better fit than a stream?
7. Intermediate. When is a stream a better fit than a queue?
8. Intermediate. How does partitioning affect ordering guarantees?
9. Intermediate. What is a dead-letter queue and when do you use it?
10. Intermediate. How does backpressure differ between queues and streams?
11. Advanced. How does the transactional outbox pattern relate to queues and streams?
12. Advanced. What happens to delivery semantics during consumer rebalance in a stream?
13. Advanced. Can you get exactly-once processing by using a stream alone?
14. Advanced. How do retention and compaction change stream behavior?
15. Advanced. How would you migrate from a queue-centric design to an event stream?
16. Scenario. Order API publishes before DB commit; phantom shipments.
17. Scenario. SQS depth flat but fulfillment slow.
18. Scenario. New search consumer group; warehouse lag jumps.
19. Scenario. Replay one year of sign-up events.
20. Scenario. One payment partition lagging tenfold.
21. Follow-up. Connection to synchronous vs asynchronous communication.
22. Follow-up. Connection to Kafka architecture.
23. Follow-up. Connection to delivery guarantees.
