# Solutions — D14-T017

## Exercise 1

A message schema describes the fields of a record. A schema registry stores those descriptions and their versions under an id. Producers and consumers embed the id and look up the schema, instead of hoping both sides deployed the same class. The registry is a dependency of the produce path if registration is required. A schema without compatibility rules is only documentation.

The failure enters when a step is skipped or repeated without an invariant: a consumer that cannot deserialize a new field or a removed field, stopping the partition.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 2

The assertion should fail when a consumer that cannot deserialize a new field or a removed field, stopping the partition.

Watch schema registration failures and deserialize errors. A test that only checks a 200 status does not lock the invariant.
