## Exercise 3

`ConcurrentHashMap` per pod duplicates ~50k entries × 20 in heap and stale reads after admin updates unless you broadcast invalidation. Redis gives one shared copy, TTL, and pub/sub invalidation at ~1ms RTT per miss. For read-heavy catalog with rare writes, Redis (or DB with cache) wins on consistency; for ultra-hot keys accessed every request, a small local LRU fronting Redis is common. Memory: 20 × heap footprint versus one cluster with eviction policy.
