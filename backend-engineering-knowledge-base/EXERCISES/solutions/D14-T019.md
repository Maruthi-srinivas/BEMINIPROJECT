# Solutions — D14-T019

## Exercise 1

Event sourcing stores the state of an entity as a sequence of events and rebuilds state by folding them. The log is the source of truth. A projection is a read model derived from the log and can be rebuilt. Snapshots speed the fold. Concurrency uses an expected version. It is a poor fit when you only needed a row and a history table.

The failure enters when a step is skipped or repeated without an invariant: a projection treated as the source of truth, or a version conflict ignored so two events both think they were next.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Event sourcing when the history is the product or the audit requirement, and you can rebuild state.

Avoid it when you only need current state and a simple update.

A good answer names the metric that would change your mind: fold time, projection lag, and version-conflict rate.
