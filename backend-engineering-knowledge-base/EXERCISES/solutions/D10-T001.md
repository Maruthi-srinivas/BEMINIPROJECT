# Solutions for D10-T001

Open this only after attempting the exercises in the topic note.

## Exercise 1

| Pattern | Store | Why |
| --- | --- | --- |
| Create order + decrement inventory atomically | SQL | Multi-row ACID invariant |
| Load product page by sku with nested media | Document or SQL + cache | Single-key read of aggregate |
| Session cart by session id | Key-value with TTL | Fast keyed read/write, ephemeral |
| User notification feed last N | Wide-column or document | Partition by user, time-ordered |
| Ad hoc finance report by month | SQL or warehouse | Joins and aggregates |

Checkout must not rely only on an eventually consistent cache for inventory.

## Exercise 2

Errors: unbounded embedded arrays bloated documents; queries filter on unindexed fields causing COLLSCAN. Fixes: paginate or externalize large arrays; add compound index on query predicates; project only fields needed for home feed; optionally precompute a slim home-feed document per user.

## Exercise 3

Postgres: simple append inserts, BRIN or btree on `(tenant_id, created_at)`, easy SQL reporting, vertical scale limits at extreme write rates. DynamoDB: partition key `tenant_id`, sort key `timestamp`, TTL for seven days, horizontal scale per tenant, limited ad hoc query without GSIs. Pick DynamoDB when write volume per tenant cluster is high and access is strictly keyed; pick Postgres when team skill and cross-tenant analytics matter more than partition scale.
