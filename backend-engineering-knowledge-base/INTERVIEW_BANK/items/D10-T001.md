# D10-T001 interview items

Domain: NoSQL Databases
Topic: SQL vs NoSQL trade-offs
Difficulty mix: beginner, intermediate, advanced, scenario, follow-up
Interview type: fundamentals, debugging, trade-off, system design
Full reasoned answers are in the topic note, section K.

## Questions

1. Beginner. What does “NoSQL” mean in practice?
2. Beginner. When is SQL still the better default?
3. Beginner. What is polyglot persistence?
4. Beginner. What is an access pattern?
5. Beginner. Does NoSQL eliminate the need for data modeling?
6. Intermediate. How do joins differ between SQL and document stores?
7. Intermediate. What consistency guarantees do you typically give up moving hot state to NoSQL?
8. Intermediate. How should teams decide between scaling SQL and adopting NoSQL?
9. Intermediate. What operational costs rise with polyglot persistence?
10. Intermediate. How do CAP theorem intuitions apply to interview trade-off questions?
11. Advanced. How would you migrate a monolithic SQL catalog to a document store without downtime?
12. Advanced. When is a NewSQL or distributed SQL layer appropriate?
13. Advanced. How do you prevent split brain between SQL and a cache of SQL rows?
14. Advanced. What signals mean you chose the wrong primary store?
15. Advanced. How do schema migrations differ in SQL versus schemaless document stores?
16. Scenario. Social feed in PostgreSQL joins explode p99—what do you propose?
17. Scenario. Finance wants SQL for money, product wants DynamoDB for everything—how do you facilitate?
18. Scenario. MongoDB with only `_id` index and slow search—is MongoDB wrong?
19. Scenario. MVP with three engineers—SQL or NoSQL?
20. Scenario. Sessions moved to Redis and users log out randomly—what failed?
21. Follow-up. How does this connect to normalization (`D07-T002`)?
22. Follow-up. What role does caching play relative to choosing NoSQL?
23. Follow-up. Where do change-data-capture streams fit?
