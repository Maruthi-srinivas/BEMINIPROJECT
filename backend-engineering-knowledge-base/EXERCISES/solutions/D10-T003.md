# Solutions for D10-T003

## Exercise 1

Patterns: fetch profile by `userId`; list open orders by `userId` sorted by time; search products by `sku`. Mongo: `_id` or `userId` index; compound `(userId, status, createdAt)` for orders; unique `sku`. Dynamo: `PK=USER#u`, `SK=PROFILE`; `PK=USER#u`, `SK=ORDER#ts`; GSI on `sku` only if query volume justifies write cost.

## Exercise 2

Hot shard if shard key is `createdAt` only or all users share `tenant=default`. Mitigate: hash suffix on `_id`, zone sharding by `userId`, or move hot tenant to dedicated cluster. Confirm with `shardDistribution` stats and `explain` IXSCAN vs COLLSCAN.

## Exercise 3

Keep payments and inventory in SQL; use Mongo for catalog and read-heavy profile aggregates with versioned snapshots from CDC. Stale catalog acceptable with `updatedAt` display; stale price is not—prices from SQL snapshot fields.
