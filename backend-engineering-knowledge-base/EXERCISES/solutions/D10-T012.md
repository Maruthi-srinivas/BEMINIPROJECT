# Solutions — D10-T012

## Exercise 1

Replication copies data so a node can fail or serve reads. Sharding splits data so no single node holds everything. Replication does not add write capacity on a single-leader system. Sharding does, and it forces a partition key. Resharding moves data. A shard that is also unreplicated is one disk away from data loss.

The failure enters when a step is skipped or repeated without an invariant: a hot shard, or a replica set of one that people called highly available.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Replication and sharding when you are separating failure tolerance from capacity.

Avoid it when you shard a dataset that fits on one machine and then pay scatter-gather forever.

A good answer names the metric that would change your mind: bytes and QPS per shard, and whether every shard has a replica.
