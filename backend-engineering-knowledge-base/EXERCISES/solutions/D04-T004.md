# Solutions — D04-T004

## Exercise 1

TCP is a connection-oriented, reliable byte stream with ordering, retransmission, and flow control. UDP is a connectionless datagram protocol: each message is independent, and the network may drop, reorder, or duplicate it. UDP does less so that the application can choose its own reliability, as DNS and RTP do. TCP's stream has no message boundaries.

The failure enters when a step is skipped or repeated without an invariant: writing a UDP protocol that assumes in-order delivery, or using TCP for a small request and paying a handshake on every call.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

Choose TCP vs UDP when you need a reliable ordered byte stream.

Avoid it when you need bounded latency and can tolerate loss, or the message is idempotent and small.
