# Solutions for D03-T001

Open this only after attempting the exercises in the topic note.

## Exercise 1

Use `getpid()` in C for PID. For TID on Linux, `syscall(SYS_gettid)` or `pthread_self()` (opaque handle, not kernel TID). Spawn two pthreads printing both values; then `fork` in a single-threaded helper or document that only the forking thread survives in the child. Expected: threads share PID; child PID differs. This solution was not executed as an automated test.

## Exercise 2

The static map is shared across request threads without synchronization. Concurrent `put` and `size` cause lost updates and torn reads (race). Fix with a concurrent map, per-request local cache, or isolate cache in one thread via actor queue. Process isolation would also work but is heavier. Root cause is shared mutable heap in one process.

## Exercise 3

Use a **process pool** (or separate sandbox containers) per render job or per tenant with tight memory and CPU cgroups, seccomp, and no shared credentials. Threads share address space; a malicious PDF exploit could read memory from other jobs. Trade-off: higher memory and cold-start latency versus stronger isolation. Thread pool is acceptable only for trusted documents with external sandboxing (e.g., cloud renderer).
