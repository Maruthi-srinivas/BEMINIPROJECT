# Solutions — D03-T021

## Exercise 1

An event loop waits for readiness events, then runs the callbacks that are already runnable, then repeats. It is one thread unless you add workers. Phases typically separate timers, pending I/O callbacks, and idle work. A long callback delays every timer. The loop is a scheduler for tasks, not a thread pool.

The failure enters when a step is skipped or repeated without an invariant: one callback that parses a huge payload and delays every other timer on the loop.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 2

The assertion should fail when one callback that parses a huge payload and delays every other timer on the loop.

Watch event-loop lag, the delay between a timer's due time and its actual run. A test that only checks a 200 status does not lock the invariant.
