## Exercise 1

```python
import random
import time


def retry_with_backoff(fn, *, max_attempts=5, base_delay_sec=0.01, jitter=0.005, max_total_sleep_sec=1.0):
    if max_attempts < 1:
        raise ValueError("max_attempts must be >= 1")
    slept = 0.0
    last_exc = None
    for attempt in range(1, max_attempts + 1):
        try:
            return fn()
        except Exception as exc:
            last_exc = exc
            if attempt == max_attempts:
                break
            delay = base_delay_sec * (2 ** (attempt - 1)) + random.uniform(0, jitter)
            if slept + delay > max_total_sleep_sec:
                delay = max(0.0, max_total_sleep_sec - slept)
            time.sleep(delay)
            slept += delay
    raise last_exc


def factorial_iter(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative")
    result = 1
    for k in range(2, n + 1):
        result *= k
    return result


def factorial_rec(n: int) -> int:
    if n < 0:
        raise ValueError("n must be non-negative")
    if n <= 1:
        return 1
    return n * factorial_rec(n - 1)
```

Acceptance notes: when the sleep budget is exhausted mid-retry, the last delay may be truncated to zero; attempts still respect `max_attempts`. This solution was not executed as a separate test file.

## Exercise 2

Using `continue` on empty rows without advancing `offset` leaves the cursor on the same page forever, or skipping rows when combined with `offset += limit` in both the for-header and the body. The invariant: after each processed page, the next query must start strictly after the highest primary key (or cursor token) already emitted, monotonically increasing. Fix: advance cursor per row or use keyset pagination instead of offset when rows can be filtered in-loop.
