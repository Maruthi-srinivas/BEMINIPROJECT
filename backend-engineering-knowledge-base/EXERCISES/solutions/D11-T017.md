# Solutions — D11-T017

## Exercise 1

A Redis transaction with MULTI/EXEC queues commands and runs them without another client interleaved. It is not a rollback journal. A command can still fail and the rest still run. WATCH provides optimistic concurrency: if the watched key changes, EXEC aborts. A Lua script runs atomically on the server and can branch. Scripts must be short because they block the single thread.

The failure enters when a step is skipped or repeated without an invariant: a Lua script that loops over a huge set and stalls every other command, or assuming MULTI rolls back.

Mark that step on the diagram. If you cannot point to a step, the explanation is still a definition, not a mechanism.

## Exercise 3

Choose Redis transactions and Lua scripts when the invariant is a few keys and a few commands.

Avoid it when you need a multi-key transaction across shards, which a single script does not give you.

A good answer names the metric that would change your mind: script duration and EXEC abort rate.
